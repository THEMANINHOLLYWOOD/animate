# File intake: what the composer does with a dropped file

Everything is read in the browser (`src/lib/intake.ts`, wired in `addFiles` in `src/components/Studio.tsx`); nothing is uploaded to be parsed. A file's kind comes from its first bytes, not its name or MIME type. Only images, PDFs and text go into model requests, and they share `ATTACH_BUDGET` (3.3 MB, under Vercel's 4.5 MB body limit); a text attachment is cut at 200,000 characters. One dependency was added: [`fflate`](https://github.com/101arrowz/fflate) (pure JS; only its unzip and zlib-inflate code is imported).

"Not verified in a browser" below means the code is type-checked and its parsing is unit-tested, but the DOM half (decoding, FontFace, canvas) has not been clicked through.

| File kind | What the app does with it now | Still missing, and the best way to do it |
| --- | --- | --- |
| **Images the browser decodes** (PNG, JPEG, WebP, AVIF, BMP, ICO) | Tile with an "In the film / Reference" toggle. Re-encoded to PNG or JPEG at ≤ 1568 px for the model; drawn by name when "In the film". | Unchanged. |
| **SVG** | Recognised with or without a MIME type. Given a width/height from its `viewBox` (Firefox draws a size-less SVG image at 0×0), a `viewBox` if it has only a size, the SVG namespace, and scaled up to 1024 px when smaller, so it is sharp as a drawn asset and as the PNG the model sees. | SVGs that reference external fonts or images render without them (browsers block those inside `<img>`): inline them with [SVGO](https://github.com/svg/svgo)-style preprocessing if it matters. Not verified in a browser. |
| **Animated GIF** | Drawn as a still (first frame); the tile says how many frames. Three later frames are attached as reference images where the browser has [`ImageDecoder`](https://developer.mozilla.org/docs/Web/API/ImageDecoder) (Chrome, Edge, Firefox 133+). | Playing the animation inside the film: decode every frame with `ImageDecoder` into a sprite sheet and add a `lib.sprite(name, t)` helper to the kit. Animated WebP/APNG are stills with no note. |
| **HEIC / HEIF** | Decoded only where the browser can (Safari 17+), then kept as a JPEG so the film opens anywhere. Elsewhere: a message saying to export as JPEG. | A decoder for Chrome/Firefox. None is small: [`heic-to`](https://github.com/hoppergee/heic-to) (libheif as WASM, maintained, LGPL-3.0, several MB) behind a dynamic `import()` is the best option; [`heic2any`](https://github.com/alexcorvi/heic2any) is unmaintained. |
| **TIFF** | Same as HEIC: Safari decodes it and it is kept as PNG; elsewhere a message. Camera raw (CR2, NEF, ARW, DNG) gets its own message. | [`UTIF.js`](https://github.com/photopea/UTIF.js) (`utif2`, ~60 kB, pure JS) behind a dynamic import decodes TIFF and several raw formats. Not added: last published 2023, rare input. |
| **PSD / PSB** | The flattened composite Photoshop stores in the file is read by a small built-in decoder (8/16-bit RGB, CMYK, greyscale; raw or PackBits) and attached as a PNG. | Layers as separate assets: [`ag-psd`](https://github.com/Agamnentzar/ag-psd) reads them (large; dynamic import). Files saved without "Maximize Compatibility" have a blank composite and can't be told apart. Tested against fixtures and `psd-tools` output, not a file written by Photoshop itself. |
| **Illustrator (.ai)** | A PDF-compatible .ai (the default) starts with `%PDF` and is sent as a PDF. Old PostScript .ai / .eps: a message to export SVG, PDF or PNG. | Nothing practical client-side for PostScript. |
| **Figma (.fig), Sketch, XD, Krita, OpenRaster, Procreate** | The file's own flattened preview is attached as a reference (plus, for .fig, the images placed in it); the message says to export frames as PNG/SVG for the real thing. | Real frames: the [Figma REST API](https://www.figma.com/developers/api#get-images-endpoint) (`GET /v1/images/:key`, needs the user's token or OAuth) renders any node to PNG/SVG server-side. The .fig binary (Kiwi) is undocumented. |
| **Video** (MP4, MOV, M4V, WebM) | Unchanged: frames sampled as references; alone, the video is recreated and its sound split into stems. | AVI/MKV/WMV/HEVC that the browser can't play get a message. Decoding them needs [ffmpeg.wasm](https://github.com/ffmpegwasm/ffmpeg.wasm) (~30 MB) or WebCodecs with a demuxer such as [Mediabunny](https://mediabunny.dev/). |
| **Audio** (MP3, WAV, M4A/AAC, OGG/Opus, FLAC; AIFF in Safari) | Becomes the film's soundtrack. Decoded, tempo and beats found with `src/lib/beats.ts` and refitted to the onsets so the grid doesn't drift, the drop found from the loudness curve. The brief gets a paragraph ("Soundtrack attached: … 128 BPM, first downbeat at 0.42 s, loudest hit (the drop) at 9.6 s … cut the film to this exact tempo … Do not plan any other music"). The file is the finished film's music clip (IndexedDB for guests, Blob for signed-in), with its beat grid; sound design skips music generation and is told to set `music` to null. A tile chip switches it to **Voiceover**: then it is transcribed at build time (existing `/api/audio`), the director gets the word timings, the clip carries captions, and no voice lines are generated. A track longer than the film plays from its start (a hint says so, with a "Make the film N s" button up to 90 s). | (1) The kit's beat clock starts at 0 s; the brief tells the model the offset of the first beat, but exact sync needs `lib.beats` to take an offset, or the clip to start early (`renderMix` in `src/lib/audio.ts` doesn't handle a negative clip start). (2) Half/double-tempo mistakes and tempo changes: [Essentia.js](https://mtg.github.io/essentia.js/) `RhythmExtractor2013` (WASM) is the robust option. (3) Music vs. voice is guessed from the file name. (4) Choosing which part of a long song to use. (5) On element-based films a dropped track is added without re-cutting the picture. Not verified in a browser; no paid call was made, so the transcription path is untested end to end. |
| **Word (.docx)** | Text extracted in order: headings, lists, tables, text boxes, footnotes and endnotes. Up to 6 embedded pictures attached as images. | Comments, headers/footers, charts and SmartArt are skipped. EMF/WMF pictures are dropped (browsers can't show them). |
| **PowerPoint (.pptx)** | Per-slide text in the deck's own order: title, bullets with nesting, tables, speaker notes. Up to 6 slide pictures attached as images. | Slide *appearance* (layout, colours, charts): render slides to images. No small client-side renderer exists; the realistic route is server-side LibreOffice (`soffice --convert-to pdf`) and sending the PDF. Chart values live in `ppt/charts/*.xml` and could be read as tables. |
| **Excel (.xlsx)** | Every sheet as tab-separated rows: shared and inline strings, numbers, booleans, dates (from the cell's number format), cached formula results. | Merged cells, charts and formulas without cached values. [SheetJS](https://docs.sheetjs.com/) covers all of it (and .xls/.numbers) at ~1 MB. |
| **OpenDocument (.odt / .odp / .ods)** | Same as their Office counterparts: text with headings, lists and tables; slides with titles and notes; sheets as rows. Pictures from `Pictures/`. | Same gaps as above. |
| **RTF** | Text extracted (control words, tables of fonts/colours and embedded pictures dropped; `\'hh`, `\u` and double-byte code pages decoded). | Embedded pictures. |
| **Keynote / Pages (.key / .pages)** | Text read from the `.iwa` files (Snappy-compressed protobuf, `TSWP.StorageArchive`), with presenter notes; the app's own `preview.jpg` and placed pictures attached. | Keynote slides come out in file order, not show order (the order is in `Document.iwa`'s slide tree). **Tested only against synthetic fixtures, never a real Keynote or Pages file**; if a file yields nothing the user is told to export PowerPoint/Word/PDF. Format notes: [iWorkFileFormat](https://github.com/obriensp/iWorkFileFormat), [SheetJS iwa notes](https://git.sheetjs.com/sheetjs/notes/src/branch/main/iwa). |
| **Numbers (.numbers)** | Preview image only, with a message to export Excel or CSV. | Cell values are in `TST.TableDataList` archives; SheetJS reads them. |
| **Old Office (.doc / .ppt / .xls)** | Recognised by signature; message to save as .docx/.pptx/.xlsx or PDF. | SheetJS reads .xls; .doc/.ppt need a CFB parser ([js-cfb](https://github.com/SheetJS/js-cfb)) plus format-specific extraction, or server-side LibreOffice. |
| **PDF** | Unchanged: sent to the model as a document. | Large PDFs exceed the request budget. Either upload once with the [Anthropic Files API](https://docs.anthropic.com/en/docs/build-with-claude/files) and reference by id, or extract text / render pages client-side with [pdf.js](https://mozilla.github.io/pdf.js/). |
| **Text of any kind** (source code, YAML, SRT/VTT, TeX, logs, XML, HTML, JSON, no extension) | Anything that reads as text is attached as text: UTF-8, UTF-16 (with or without a BOM) and legacy single-byte files (decoded as Windows-1252). A `.ts` source file is no longer taken for MPEG video. | Other legacy encodings are guessed as Windows-1252. Subtitles are sent as text, not placed as captions on the film's timeline (`src/lib/captions.ts` could take them). |
| **Fonts** (TTF, OTF, WOFF, WOFF2) | Loaded with the FontFace API under the family name read from the font's `name` table (weight and italic from `OS/2`, a weight range for variable fonts), shown as a tile set in the font, and the brief is told "Brand font attached: use family 'X' for display type". Names are made safe for the canvas font shorthand ("Exo 2" → `Exo2`). Kept with the film and reloaded in the Studio and the editor: in IndexedDB for guests, in the account's `fonts/` folder (refs on the film as `fonts`, like `assets`) when signed in. | WOFF2 family names come from the file name (tables are Brotli-packed; `DecompressionStream("brotli")` is not in Chrome). TTC collections are refused by FontFace. Not verified in a browser. |
| **Zip archive** | Opened: up to 12 files (30 MB each, 60 MB total) are taken one by one as if dropped; system litter is skipped; the rest are counted in a message. | Nested zips, and gzip/tar/7z/rar (message: unpack first). |
| **Anything else** (programs, disk images, databases, 3D models, After Effects, InDesign, MIDI, e-books…) | Never skipped silently: the message names what the file is and what to drop instead. The file picker no longer filters by type. | See the rows below for the ones worth building. |
| **After Effects / Lottie** | .aep: message to render MP4. A Lottie `.json` is attached as text; `.lottie` (a zip) hands its JSON over the same way. | Play it: [lottie-web](https://github.com/airbnb/lottie-web)'s canvas renderer can render any frame, so a Lottie could be sampled like a video or drawn as an animated asset. |
| **3D models** (glTF/GLB, OBJ, FBX, USDZ, .blend) | Message: render a still or a turntable video. | [three.js `GLTFLoader`](https://threejs.org/docs/#examples/en/loaders/GLTFLoader) could render a turntable to frames client-side (~600 kB, dynamic import). |
| **Figma links** | Not handled (treated as a site link by the brand reader). | Figma REST API with OAuth, as above. |
| **YouTube / Vimeo links** | Not handled. | Can't be downloaded in the browser (CORS, terms of service). A server-side fetcher (yt-dlp) is a legal and hosting question, not a technical one; [oEmbed](https://oembed.com/) gives title and thumbnail only. Ask for the file. |
| **Live URLs** | Unchanged: `/api/brand` reads colours, fonts, logo and preview image. | A screenshot of the page: headless Chromium on the server ([`@sparticuz/chromium`](https://github.com/Sparticuz/chromium) with Playwright) or a screenshot API. |
| **Google Docs / Slides / Sheets links** | Not handled. | Export endpoints need the user's Google auth; ask for a download as .docx/.pptx/.xlsx/PDF, which now work. |
